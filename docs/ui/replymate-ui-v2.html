自动迭代的规矩
只在采纳后
没被采纳的生成不进画像，避免用"废稿"训练偏见
一次一条
每次最多改 1 条，改哪条必须能指向具体某次对话
不做静默
画像一改，结果页必有提示条 + 撤销，不允许后台悄悄变
可整体关闭
关掉后档案退化为手动填写的静态卡
换一批 演化提示不打断选卡，也不抢按钮位
结果页 · 演化提示
轻提示条，不弹窗、不阻断，随时可撤
画像怎么演化 · 四个问题
何时提炼
每次采纳后写入一条本地事件；攒够 3 条或距上次 ≥7 天，异步提炼一次（WorkManager，可被打断）
用哪些数据
只喂已采纳的那条候选 + 你手改后的最终文本；不喂对方原话、不喂未采纳的草稿
原文怎么办
提炼在本机 7 天窗口内完成；产出只有 4 条摘要 + 时间戳，原话照常被清理，不进画像
模型挂了呢
不更新，不报错、不弹窗；下次攒够再试。宁可不更新，也不要瞎更新
为什么必须"显式 + 可撤销"
自动迭代最典型的翻车是自我强化：模型第一次判错"他不喜欢寒暄"，之后每次生成都更简短，你越用越觉得对，画像越走越偏，最后变成一个你不敢信任的黑盒。

所以规矩定死：一次只动一条、必须指向具体某次对话、必须在结果页告知、必须能撤销。做不到这四条，这个功能就不该上线。
一条红线
画像本身是"对某个人的判断"，比聊天记录更敏感。所以：不出本机、不上传、不导出到备份 JSON，且清空数据时优先删它。
