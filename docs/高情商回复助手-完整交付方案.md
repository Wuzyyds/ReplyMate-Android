## 0. 一页结论

| 维度 | 结论 |
|---|---|
| 形态策略 | **B（截图/粘贴）是底座，A（读屏+悬浮窗）是加速器**。生成能力不得依赖无障碍是否开启 |
| 移动端框架 | **原生 Kotlin + Jetpack Compose**（加权 4.05 / 5），Flutter 2.70；悬浮面板用 **XML + View** 预 inflate，保证唤起 ≤300ms |

| 模型 | 主力 DeepSeek-V3.2，分类/解释用 GLM-4-Flash（免费） |
| 成本 | 每天 20 次生成约 **¥2.2/月**，可忽略 |
| 工期 | M1~M4 共 **6~9 周**（业余时间约 3 个月） |
| 一条红线 | **只回填输入框，永不自动发送** |

## 1. Phase 1 · 需求定义

### 1.1 需求五要素

| 要素 | 内容 |
|---|---|
| 业务目标 | 在「不知道怎么回 / 怕说错话」的瞬间，30 秒内拿到 3 条能直接用的得体回复 |
| 目标用户 | 用户本人（单用户），职场沟通与求职沟通高频发生者 |
| 核心场景 | 微信（领导/同事/朋友/暧昧/家人）、BOSS 直聘（HR/猎头）、钉钉/飞书（客户/同事） |
| 关键流程 | 触发 → 取对话上下文 → 选关系与目标 → 出 3 条候选 + 解释 → 回填/复制 → 发送（人工） |
| 约束条件 | 单人开发；无后端运维意愿；手机为唯一运行环境；聊天内容含第三方信息，隐私敏感 |

### 1.2 场景优先级（自用视角）

| 顺序 | 场景 | 理由 |
|---|---|---|
| 1 | 职场 / BOSS 沟通 | 回复范式明确、有客观好坏标准（是否得体、是否踩雷），验证成本最低 |
| 2 | 亲密关系 | 使用频次高、情绪价值强，但好坏主观，适合第二版调 prompt |
| 3 | 泛社交应酬 | 场景分散、单次价值低，用话术库覆盖即可，不必单独优化 |

### 1.3 用户故事（精选 8 条）

1. 作为使用者，我在微信里点悬浮球就能取到最近 3 轮对话，以便不用手动复制。
   验收：点一次球，2 秒内悬浮面板显示识别到的消息条数与角色标注。
2. 作为使用者，我想一键切换「对方说 / 我说」，以便读屏判错角色时立刻纠正。
   验收：误判时点一下即改，且不触发重新取词。
3. 作为使用者，我想设定对方是「领导 / HR / 客户 / 朋友 / 暧昧 / 家人」，以便语气自动匹配。
   验收：不同关系下同一句话生成结果明显不同。
4. 作为使用者，我想选「拒绝 / 催进度 / 道歉 / 请假 / 暖场 / 谈条件」，以便不用自己描述诉求。
   验收：6 个目标各出一组可用回复。
5. 作为使用者，我想一次看到 3 条不同风格的候选，以便挑一条最像自己说话的。
   验收：三条覆盖「稳妥 / 有温度 / 直接」，且长度均 ≤ 80 字。
6. 作为使用者，我想看到一句「为什么这样说」，以便下次自己能说。
   验收：每批结果附带 1 句策略解释（≤ 40 字）。
7. 作为使用者，我想点一条候选就自动填进输入框，以便省掉复制粘贴。
   验收：L1 成功时输入框内文字被替换；失败时自动落到剪贴板并提示。
8. 作为使用者，我想在 App 读不到界面时有兜底路径，以便工具永远能用。
   验收：分享图片或粘贴文本 → 同样出 3 条候选。

### 1.4 MVP 边界

**第一期做（P0/P1）**：读屏取词、截图 OCR、粘贴导入、关系与目标选择、3 条候选+解释、回填三级降级、历史记录、预置话术库、模型与 Key 设置。

**第一期坚决不做**（避免过度设计）：

| 不做 | 理由 |
|---|---|
| 自动点击发送 | 误发一条给领导，工具就废了；风险收益完全不对等 |
| 账号体系 / 云同步 | 单机单用户，同步是纯负债 |
| 多模型面板 / 自动路由 | 一个主力 + 一个免费兜底足够 |
| RAG / 长期记忆检索 | 6 条上下文已覆盖绝大多数场景 |
| 语音输入 | 与核心价值无关，属锦上添花 |
| 群聊多人语境分析 | 节点树无法可靠区分发言人，投入产出比极低 |
| 自研 OCR / 自研纠错 | 标点缺失交给模型补全，不写正则 |
| 商业化 / 埋点 SDK | 自用不需要 |

### 1.5 待确认（影响适配顺序，不阻塞开工）

1. 手机品牌与 Android 版本（决定 OEM 引导页要覆盖哪几家）
2. 四个 App 的实际使用频率排序（决定 M3 适配优先级）
3. 是否接受悬浮球常驻屏幕（不接受则 A 路线改为通知栏入口）

## 2. Phase 1 · 产品定义（PRD 摘要）

### 2.1 一句话定位

> 它替你解决「盯着输入框半分钟打不出一个字」的那个瞬间——不是替你说话，是帮你把想说的说清楚。

### 2.2 双路径流程与降级

**路径 A（读屏，主）**
悬浮球点击 → 判定前台包在白名单 → 定位输入框锚点 → 提取可见消息 → 角色标注 → 悬浮面板选关系/目标 → 流式生成 → 点选候选 → TextInjector 回填 → 人工发送

| 步骤 | 失败点 | 降级 |
|---|---|---|
| 取词 | 无障碍被关 / 节点树为空 / 非白名单 App | 2 秒超时 → 提示走截图或粘贴 |
| 角色标注 | 居中气泡、无头像 | 悬浮窗给「对方/我」切换按钮 |
| 生成 | 超时 / 解析不合法 / Key 失效 | 三支**互斥**，优先级 **Key > 超时 > 解析**：Key 错跳设置并高亮字段；超时保留进度文本 + 重试；解析不合法则整批换离线模板 + 角标，并明说「这次没生成成功，给你 3 条备用说法」。失败一律**原地替换** `GenerateState.candidates`，不清空再渲染——否则用户会看到内容凭空消失 |
| 回填 | WebView 输入框不吃 ACTION_SET_TEXT | L2 剪贴板+PASTE → L3 提示长按粘贴 |

**路径 B（导入，底座）**
分享图片到本 App / Photo Picker 选图 / 手动粘贴文本 → OCR 或直接取文本 → **识别结果可编辑修正**（OCR 常丢标点，允许手改错别字，不要求重截图）→ 选关系/目标/风格 → 生成 → 点选 → 复制 → 回原 App 粘贴

**A→B 必须一步切换**：读屏返回空时不跳回首页，生成页原地进入「已降级态」——顶部横幅「没读到内容」+ 两个按钮「改用截图」「改用粘贴」，**已选的关系/目标/风格全部保留**。不允许出现「这条路走不通，你自己想办法」。

### 2.3 功能清单（以 PRD 编号为准）

| 编号 | 功能 | 优先级 | 验收要点 |
|---|---|---|---|
| F-01 | 无障碍读屏抓取 | P0 | 只读**屏幕内可见**消息（通常 8–12 条，上限 20），**不滑动、不滚屏**；三端各 5 段真实会话，末次成功 ≥9/10；全程无界面跳动 |
| F-02 | 悬浮球与一键回填 | P1 | 3 个目标 App 内可见可拖拽；回填文本与所选候选差异 ≤1 字符 |
| F-03 | 截图 OCR | P1 | 清晰中文截图准确率 ≥95%，单张 ≤3s，断网可用 |
| F-04 | 粘贴文本导入 | P0 | ≤3000 字，超出截断并提示；空内容不可提交 |
| F-05 | 关系与目标设定 | P0 | 7 关系 × 6 目标必填，缺一「生成」置灰；2 次点击内完成 |
| F-06 | 3 条候选生成 | P0 | 结构稳定 3 条；首字 ≤2.5s、**3 条可点 ≤6s**（口径见 §2.5）；空返回率 <2% |
| F-07 | 为什么这样说 | P0 | 3 条全带 1–2 句解释，**3 句互不相同**；缺失即判缺陷；兜底模板须打「离线模板 · 未调用模型」角标，**来源由数据字段决定，不许 UI 推断** |
| F-08 | 复制 / 回填双通道 | P0 | 点复制后粘贴内容与候选一致 |
| F-09 | 风格档位 | P1 | 稳/暖/机灵，切档后 3 条文本差异 ≥60% |
| F-10 | 历史记录 | P1 | 最近 200 条，可按关系筛选，单条可删 |
| F-11 | 联系人档案 | P2 | 建档后生成命中，结果页显示「已参考：XX 的档案」 |
| F-12 | 话术库 | P2 | 断网可用，一键复制与自定义新增 |
| F-13 | 模型与 Key 设置 | P0 | baseUrl / apiKey / modelName 可填，连通性自检返回耗时与错误码 |

P0 占比：7/13 = **53.8%**（符合 ≤60%）。枚举值：关系 7 值（朋友/暧昧/家人/HR/领导/同事/客户）、目标 6 值（维持/推进/拒绝/致歉/谈条件/结束对话）、风格 3 值（稳/暖/机灵）。

生成方式：**单次流式请求**，一次输出结构化 JSON（3 个 candidate，各含 `text` + `why`）。流式期间先出进度态文字（**2.5s「首字」指这里**），但 **3 张卡要等整批校验通过后一次性上屏**——不做逐条渲染，否则会出现「点完被整批回滚」的竞争。不做 3 并发：并发让输入成本 ×3，且 3 条风格容易趋同。解析失败重试 1 次（temperature 降 0.3），仍失败**整批**回落本地话术库 + 通用解释，并打「离线模板 · 未调用模型」角标，**绝不给 1 条或空解释**。

| P-02 | 生成页 | 对话原文（可折叠编辑）、关系行、目标行、风格档位、3 张候选卡（解释 + 复制/回填 + **来源角标**）、换一批 | ← P-01；→ P-05 |

### 2.5 非功能需求

| 项 | 要求 |
|---|---|
| 时延 | **首字（第一个可见字符，非第一张卡可点）≤2.5s**；3 条完整 ≤6s（4G），首卡可点约 4.2s；悬浮面板唤起 ≤300ms；回填 ≤300ms |
| 离线可用 | **可用**：历史、话术库、联系人档案、已缓存候选、粘贴后查看；**不可用**：生成、OCR（模型未下载时）。离线时生成按钮置灰并说明原因，不许空转 |
| 存储 | 全本地 Room；对话原文默认 7 天自动清理（可调）；单库上限 50MB，超限从最旧 `conversation` 删起；图片不持久化（OCR 后即弃）；指标表 `usage_event(id, type, ts, app_pkg, latency_ms, sim_score, is_adopted, relation_enum, goal_enum, style_enum)`——请求发起时快照写入三个枚举，采纳时同行 update `is_adopted`/`sim_score`（不新增行，避免采纳率分母重复计数），表内无原文、无候选文本、无联系人名 |
| 隐私 | 截图与读屏原文**不出本机**；仅上传 `PromptBuilder` 产出的文本片段，生成前可展开「查看将要发送的内容」；Key 存 EncryptedSharedPreferences；**零第三方 SDK**（含崩溃上报、统计、广告） |
| 包体 | ≤ 30MB（OCR 模型按需下载约 20MB） |

### 2.6 自用版指标（以 PRD 第七章为准，数据全部来自本地 `usage_event`）

| 指标 | 目标 | 口径 |
|---|---|---|
| 单次生成到发出耗时 | 中位数 ≤90s | 点悬浮球/进生成页 → 复制或回填成功 |

## 3. Phase 1 · 技术方案（要点，详见 `技术研发方案.md`）

### 3.1 选型决策

**框架：原生 Kotlin + Compose（4.05）优于 Flutter（2.70）**
权重：系统能力适配 45% / 开发速度 20% / 学习成本 20% / 维护成本 15%。
本项目约 70% 工作量在无障碍节点树、悬浮窗、输入框回填、OCR，全是系统 API；Flutter 每项都要跨端往返，省下的界面时间会成倍还回。

**后端：第一期直连模型 API**
单用户、APK 不外传，Key 风险用 Keystore 加密 + 控制台月限额覆盖；代理层对自用工具是纯负债。预留 `LlmClient` 接口，需要 prompt 热更新时再上 CF Workers。

**模型设置泛化（F-13）**：不做厂商硬编码，`baseUrl / apiKey / modelName` 三项可填 + 「连通性自检」按钮（发 8 token 的 ping，回显耗时与错误码）。预置 DeepSeek / 通义 / 智谱 三个模板一键填充。

**性能实现三招**
1. **后缀换一批**：固定前缀（角色 + 规则 + 输出 JSON schema + few-shot）走厂商前缀缓存，只把「换一批」后缀轮换（温度升 0.1）。
2. **悬浮面板不走 Compose 冷组合**：XML/View 预 inflate、常驻 attach（`visibility=GONE`），点击只切 visible，保证 ≤300ms。主 App 仍用 Compose。
3. **prompt 前缀固定 + 关闭思维链 + `max_tokens≈600` + 连接池复用 + DNS 预解析**。

**双层降级 + 整批原子性**：网络/HTTP 错误 → 重试 1 次 → 仍失败回落本地话术库；结构解析失败 → 重试 1 次（温度降 0.3）→ 仍失败同样回落。**一批 3 条只能是全模型或全模板，禁止混批**（`source` 只有 `model` / `offline_template` 两值）。理由是部分解析成功时单条校验无法判断某条是否残缺，混批比整批替换风险更高。角标文案「离线模板 · 未调用模型」，**中性灰、不用警告色**（这不是错误，是备选方案）；来源由字段决定，**UI 不许推断**；降级提示是**页面内一句文案，不是弹窗**。

### 3.2 读屏算法（不硬编码任何 App）

1. 前台包白名单校验（微信/BOSS/钉钉/飞书）
2. DFS 找输入框锚点：`isEditable` 且可见，取面积最大
3. 从输入框向上回溯 2~4 层定位消息容器（子节点 ≥2 且高度 >30% 屏）
4. 收叶子节点（text/contentDescription 非空、1~200 字、完全可见）
5. 按 `bounds.top` 排序 = 阅读顺序
6. 只取屏幕可见节点 → 天然排除历史消息；`sessionFingerprint` 变化即清缓存
7. 角色判定用**双信号投票**：水平位置（右 1/3 = 我）+ 头像相邻方向；冲突标 UNKNOWN 交用户一键修正

**F-01 硬约束**：**不滑动、不滚屏**，一屏通常 8–12 条，硬上限 20 条；送模型的只取最近 6 条。`MessageExtractor` 内**禁止出现任何 `ACTION_SCROLL_*` 调用**（20 只是数组防御上界，够不到就按实际条数走，降级判断看「有没有对方最后一句」而非条数）。为凑条数去程序化滚动会移动用户屏幕、有误触风险，还可能触发「已读」，收益为零。

**自学习**：首次跑通后把「输入框 viewId + 容器相对深度」写入 `capture_rule`，后续优先命中。读树为空 2 秒超时直接降级，绝不重试。

### 3.3 回填三级降级

| 级别 | 手段 | 适用 |
|---|---|---|
| L1 | `ACTION_FOCUS` + `ACTION_SET_TEXT` | 原生 EditText（多数） |
| L2 | 写剪贴板 + `ACTION_FOCUS` + `ACTION_PASTE` | WebView 输入框（部分飞书/BOSS） |
| L3 | 写剪贴板 + 悬浮窗提示「长按粘贴」 | 全部失败时兜底 |

**回填失败的处理规则**：L2 失败后**强制写剪贴板并 Toast「已复制，请长按粘贴」**——不抛异常、不弹错误对话框、不锁 UI。用户永远不空手，这是「兜底」而不是「报错」。

### 3.4 悬浮窗关键参数

- `TYPE_APPLICATION_OVERLAY` + `FLAG_NOT_FOCUSABLE`（不抢焦点、不弹输入法）
- Android 14 需 `foregroundServiceType="specialUse"` + `PROPERTY_SPECIAL_USE_FGS_SUBTYPE`
- 位置：按输入框 `bounds.top` 贴其上方 8dp，键盘弹起时重算；贴边收起为 24dp 圆点

### 3.5 成本控制

最近 6 条消息 / 单条 200 字 / 输入上限 1500 token / 模板命中直接返回（覆盖约 30%）/ 30 分钟内同输入复用结果。

**月成本：DeepSeek 约 ¥2.2，qwen-plus 约 ¥1.1。可选型权重应放在质量而非单价。**

## 4. Phase 2 · 质量保障（自用裁剪版）

> 自用项目不做全量测试体系，只保留「能保证每天用不出事」的最小门禁。

### 4.1 质量门禁

| 门禁 | 标准 |
|---|---|
| 核心链路 | 读屏 → 生成 → 回填 成功率 100%（4 App 各连跑 3 次） |
| 崩溃 | 连续 7 天使用零崩溃 |
| 主流程时延 | 首条候选 P95 ≤ 5s |
| 回填成功率 | L1+L2 ≥ 90% |
| 无障碍存活 | 被杀后 15 分钟内可被用户感知（通知/悬浮球消失） |
| 数据安全 | Key 不以明文出现在界面、日志、崩溃堆栈 |

### 4.2 真机回归清单（每次改动后跑一遍）

1. 冷启动 → 粘贴文本 → 出 3 条 → 复制成功
2. 微信：读屏取词条数正确、角色标注正确
3. 微信：点候选 → 输入框被替换，且**未自动发送**
4. BOSS 直聘：同一流程可用
5. 钉钉 / 飞书：至少 L2 降级可用
6. 分享图片进 App → OCR → 出候选
7. 杀掉无障碍服务 → 重进 App 有提示且可一键跳设置
8. 键盘弹起 → 悬浮窗不遮挡输入框
9. 断网 → 有明确错误提示，不白屏
10. 重启手机 → 悬浮球与无障碍状态符合预期
11. 构造畸形返回：只回 2 条 / 3 条解释同一句 / 解释为空 / 某条 `text` 为空串 / `text` 只有空格 / 缺 `why` 字段 / JSON 截断 / 字段类型错 —— 任一种都必须**整批**降级为离线模板 + 打「离线模板 · 未调用模型」角标，不得只降一条。**空值判定统一 `trim()` 后判空**，`text` 与 `why` 同一标准
12. 任一批结果中 3 张卡的来源角标完全一致（全模型或全模板），不存在混批；降级时页面出现「这次没生成成功，给你 3 条备用说法」文案

## 5. Phase 3 · 发布（侧载，无上架）

| 项 | 做法 |
|---|---|
| 签名 | 一次性生成 keystore，**永久备份**。丢签名的后果是后续版本无法覆盖安装，只能卸载重装（数据全丢） |
| 打包 | `./gradlew assembleRelease`，开启 R8 混淆，关闭 debug 日志 |
| 安装 | 手机允许「安装未知来源应用」；Google Play Protect 可能提示风险，选择忽略 |
| 回滚 | 每次发布保留上一版 APK；数据库结构只增不删，升级用 Room Migration，**禁止 destructive migration** |
| 数据备份 | 发布前导出一次 DB JSON（设置页提供），放电脑留档 |
| 审核风险 | 无商店审核；唯一风险是厂商「风险应用」提示与后台管控 |

## 6. Phase 4 · 运维（单机版）

## 7. Phase 5 · 复盘（替代增长运营）

自用产品没有获客与留存，但有「是否真的在用」的问题。每周日花 3 分钟看四个数：

| 指标 | 含义 | 动作 |
|---|---|---|
| 本周生成次数 | 是否成为习惯 | < 10 次 → 检查摩擦点在哪一步 |
| 采纳率 | 回复是否可用 | < 50% → 调 prompt 与话术库 |
| A 路径成功率 | 读屏是否可靠 | < 70% → 优先修适配，而非加功能 |
| 最长耗时 | 体验断点 | > 40s → 查网络或模型超时 |

**v2 候选功能**（按数据决定，不提前做）：一键截屏（`takeScreenshot` API 30+）、语音输入、话术库扩充到 300 条、双人语境分析、prompt 云端热更新。

## 8. 里程碑

| 阶段 | 周期 | 交付物（对应 PRD 编号） | 验收 |
|---|---|---|---|
| M1 闭环验证 | 1-2 周 | P0 全量：F-04 粘贴导入、F-05 关系/目标、F-06 三候选、F-07 解释、F-08 复制/回填、F-13 Key 设置；含 30 条最小话术种子（保证降级不空） | 真机粘贴对话，10 秒出 3 条，复制成功 |
| M2 主路径打通 | 2-3 周 | F-01 读屏取词、F-02 悬浮球 + TextInjector 三级降级 | 微信点球 → 出 3 条 → 点一条进输入框 |
| M3 多 App + 兜底 | 2 周 | F-03 截图 OCR + 分享/选图入口；BOSS/钉钉/飞书 适配 + `capture_rule` 自学习；话术库扩到 100 条 | 4 App 各连跑 3 次成功，OCR 路径可用 |
| M4 打磨 | 1-2 周 | F-09 风格档位、F-10 历史；心跳自检、OEM 引导页、结果复用、备份导出 | 连续 7 天无崩溃，无障碍被杀可感知 |

**F-11 联系人档案、F-12 话术库的浏览/自定义界面放 v2**。F-12 的「内置种子」不延后——它是解析失败时的唯一兜底，M1 就必须有最小集合。

**M1 是硬顺序**：先把「文本 → 模型 → 3 条 → 复制」跑通，再叠加系统能力，避免一开始死在无障碍调试上。

## 9. 风险与红线

| # | 风险 | 应对 |
|---|---|---|
| 1 | 无障碍被系统杀 | 前台服务 + 15 分钟心跳 + 通知一键跳设置 + 降级到通知栏入口 |
| 2 | 微信改版导致节点结构变化 | 不硬编码 resourceId，只用「可编辑+面积+位置」；超时切 OCR |
| 3 | 部分 App 输入框吃不下 SET_TEXT | L1→L2→L3 责任链，失败记入 capture_rule 下次直接走 L2 |
| 4 | 模型 Key 泄露 | Keystore 加密、不明文回显、控制台月限额 |
| 5 | 悬浮窗与输入法冲突 | FLAG_NOT_FOCUSABLE、按输入框定位、键盘弹起重算 |
| 6 | 误发事故 | **永不自动发送**，只回填，发送必须人工点 |

**隐私红线**：聊天内容含对方信息。只上传文本、绝不上传图片原文、不做任何云端存储、不接第三方统计。真机截图用于调试时注意打码。

```
技术债务（明确接受）：无 MediaProjection 录屏、无多设备同步、无离线小模型、capture_rule 不跨设备共享
```

## 11. V1.3 增量交付（2026-11-12 定稿）

### 11.1 变更摘要

产品从「回复助手」扩为「表达助手」，但**页面数不变（仍 7 页）**，只加一个「模式」维度：回复 / 发圈 / 润色。新增表情三档、朋友圈文案（一键复制）、润色双入口、联系人画像自动演化。

### 11.2 版本归属

| 阶段 | 新增内容 | 增量工期 | 依赖 |
|---|---|---|---|
| M1 | 模式切换 + 表情三档 + 润色（独立模式） | +2.5 天 | 无（复用生成管线） |
| M3 | 朋友圈纯文字 + 一键复制 + 折叠条弹层 | +2.5 天 | 场景模板库 |
| M4 | 联系人画像自动演化 + 变更可撤销 | +2 天 | 需 F-10 历史与采纳数据 |
| v1.1 | 朋友圈带图（Vision）+ 上传说明 + 开关 | +3 天 | 需多模态模型 |

**总工期：6~9 周 → 9~12 周**（业余约 3.5~4 个月）。

### 11.3 与既有约束的冲突及裁决

| 冲突点 | 原约束 | 裁决 |
|---|---|---|
| 图片上传 | 「截图与读屏原文不出本机」 | 仅发圈路径可上传，首次显式说明 + 可关闭；回复/OCR 路径维持零上传 |
| 采纳率指标 | ≥55% 统一口径 | 按 `task_type` 分算，发圈不参与采纳率 |
| 悬浮面板 300ms | 面板内元素增加会拖慢 | 悬浮**只保留回复模式**，表情只给两档；新增元素一律预 inflate |
| 3 条差异 ≥60% | 未定义计算基准 | 先剥 emoji 再算，emoji 不计入差异 |
| 回填 | 所有候选都要能回填 | 发圈/独立润色页无目标输入框，**隐藏**回填按钮（不置灰） |

### 11.4 交付前置条件

1. Android Studio + SDK 未安装（本机仅 JDK 17），首次运行需先装 IDE 与 `platforms;android-35`、`build-tools;35.0.0`；
2. 模型型号不得写死在代码：预置模板放 `assets/models.json`，`deepseek-chat` 已于 2026-07 退役，现用 `deepseek-flash`；
3. Key 不入库、不进备份、不明文回显。
